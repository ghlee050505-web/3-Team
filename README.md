## 3. 우리가 일하는 방식 (Agile)

수업에서 배운 애자일 요소를 그대로 팀 운영에 적용합니다.

- **스프린트**: 1주 단위. 매주 화요일 수업 시간에 리뷰와 회고를 진행합니다.
- **칸반 보드**: GitHub Projects를 사용합니다. 컬럼은 `Backlog → Ready → In progress → Done` 입니다.
- **이슈**: 모든 작업은 마크다운 이슈로 등록합니다. 아래 형식을 따릅니다.
  ```markdown
  ### 작업 제목
  #### 작업 내용
  - [ ] 세부 작업 1
  - [ ] 세부 작업 2
  #### 완료 조건
  - 무엇이 되면 끝난 것인지
  #### 관련 이슈/리소스
  - 참고 링크, 연관 이슈
  ```
- **마일스톤**: 굵직한 목표는 마일스톤으로 묶고, 모든 이슈에 마일스톤을 지정합니다.
- **Daily Scrum**: 슬랙 채널에 "어제 한 일 / 오늘 할 일 / 막힌 것" 세 줄로 공유합니다.
- **회의록**: [`회의록/`](./회의록) 폴더에 날짜별로 남기고, 마지막에는 반드시 **Next step**을 적습니다.

## 6. 협업 규칙

- **브랜치**: `main`은 항상 배포 가능한 상태로 유지합니다. 작업은 `feat/기능명`, `fix/버그명`, `docs/문서명` 브랜치에서 합니다.
- **커밋 메시지**: `타입: 내용` 형식. 타입은 `feat`, `fix`, `docs`, `style`, `chore` 중 하나를 씁니다.
- **Pull Request**: `main`에 합칠 때는 PR을 열고 팀원 1명 이상의 확인을 받습니다.
- **이슈 연결**: 커밋이나 PR 본문에 `#이슈번호`를 적어 이슈와 연결합니다.
